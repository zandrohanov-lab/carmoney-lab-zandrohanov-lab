# Проверка формы заявки в Android-эмуляторе

Дата проверки: 18.10.2026.

## Результат

После отправки формы с пробегом `400001` км система показала:

- Решение: `REVIEW` (значение API: `review`; интерфейс отображает его заглавными буквами).
- LTV: `50 %`.
- Возраст авто: `7 лет`.
- Одобренный лимит: `0 ₽`.
- Номер заявки: `31`.

Скриншот результата сохранён в `docs/hw2/mobile_check.png`.

## Выполненные шаги

1. Проверил backend: `http://localhost:8080/health` вернул HTTP 200.
2. Запустил Android AVD `cim` командой эмулятора и дождался `sys.boot_completed=1`.
3. Через MCP `claude-in-mobile` проверил устройство: `emulator-5554` был активен.
4. Открытие URL через MCP `system.open_url` не удалось: действие было недоступно для browser platform.
5. Открыл форму в браузере эмулятора через MCP-вызов Android intent: `http://10.0.2.2:8080/`. Адрес `10.0.2.2` нужен, чтобы из Android-эмулятора обратиться к сервису на хост-машине.
6. Проверил загрузку формы: поле `mileage` содержало начальное значение `84000`.
7. Первоначальный ввод `400001` добавился к существующему значению, поэтому поле стало `84000400001`.
8. Стер значение и ввёл `400001`. MCP подтвердил значение поля.
9. Первая попытка нажать «Отправить заявку» попала в открытую экранную клавиатуру. В поле оказался лишний символ, значение стало `4000012`.
10. Закрыл клавиатуру, удалил лишнюю `2`, повторно проверил значение `400001`.
11. Закрыл клавиатуру и нажал «Отправить заявку». После ответа появился блок «Решение» со значениями, указанными выше.
12. Вызов MCP `screen.capture` создал скриншот, но текущая модель не поддерживает просмотр или сохранение вложенного изображения. Поэтому экран эмулятора сохранён напрямую через `adb exec-out screencap -p` в `docs/hw2/mobile_check.png`.
13. Проверил созданный файл: PNG, 1080×1920, RGBA.

## Ограничения

- PNG не был визуально прочитан моделью: вход изображений не поддерживается. Значения результата подтверждены accessibility-деревом MCP после отправки формы.
