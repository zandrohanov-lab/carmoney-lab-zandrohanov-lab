# Issue CASE-09-2. PhraseRepository: чтение дефолтной фразы группы

## Метки
epic: case-09
size: S

Обоснование size: **S** — один read-only класс по образцу существующего
`ApplicationRepository` (`backend/src/Repository/ApplicationRepository.php`) и один файл
feature-тестов. Один метод, одна зона ответственности, нет схемы и нет оркестрации.
Не M: не нужна логика отбора заявок, рендера или записи протокола.

## Цель
Появляется репозиторий только для чтения, который по типу решения возвращает активную
дефолтную фразу его группы или сигнал «нет фразы» для пропуска заявки.

## Контекст
- Спека: `docs/spec/spec_CASE-09.md`, REQ-CASE-09-08, REQ-CASE-09-09, REQ-CASE-09-12
  (AC-CASE-09-10 — условие пропуска).
- Таблица фраз и сид созданы в issue_CASE-09_1 (зависимость).
- Образец репозитория: `backend/src/Repository/ApplicationRepository.php:12-114`
  (конструктор с PDO, методы возвращают массивы).
- Подключение: `CarMoneyLab\Database::connect()` (`backend/src/Database.php:15`).

## Требования
- **REQ-CASE-09-08.** Новый класс `CarMoneyLab\Repository\PhraseRepository`
  (`backend/src/Repository/PhraseRepository.php`), только чтение: методов записи нет.
- **REQ-CASE-09-09.** Метод вида `findDefaultForDecision(string $decision): ?array`
  возвращает активную фразу с флагом «дефолтная» из группы `$decision`
  (`approve`/`review`/`reject`): как минимум `id` и текст фразы.
- **REQ-CASE-09-12.** Если в группе нет активной фразы или дефолтная не помечена флагом —
  метод возвращает `null` (это сигнал пропуска для сервиса из issue_CASE-09_5).
- Неактивная дефолтная фраза не возвращается; фразы чужих групп не возвращаются.

## Не входит в задачу
- Логика пропуска заявок и счётчики — issue_CASE-09_5.
- Редактирование фраз из системы — владелец списка юрист (REQ-CASE-09-08).
- Кэширование и оптимизации чтения.
