# Issue CASE-09-3. Отбор заявок в батч и выбор последнего решения

## Метки
epic: case-09
size: M

Обоснование size: **M** — один репозиторий, но с нетривиальным SQL: соединение
`applications` + `decisions`, anti-join с протоколом, выбор последнего решения
(максимальный `created_at`, при равенстве — максимальный id). Пять граничных критериев
приёмки (AC-CASE-09-02 … AC-CASE-09-06) требуют отдельного теста каждый. Не S из-за
объёма граничных случаев, не L: одна зона ответственности, только SELECT, без записи
и без оркестрации.

## Цель
Появляется репозиторий-источник кандидатов батча: все заявки `decided` с решением
и без записи в протоколе, к каждой присоединено последнее решение по `created_at`/id.

## Контекст
- Спека: `docs/spec/spec_CASE-09.md`, REQ-CASE-09-02, REQ-CASE-09-04, REQ-CASE-09-17
  (AC-CASE-09-02, -03, -04, -05, -06 — границы).
- Таблица протокола создана в issue_CASE-09_1 (зависимость).
- Схема: `applications` (`db/schema.sql:4-13`), `decisions`
  (`db/schema.sql:30-41`); уникальности решений по `application_id` нет — решений
  может быть несколько.
- Сид: `db/seed.sql:5-29` — 24 заявки `decided`; решения `db/seed.sql:57-81`.
- Образец: `backend/src/Repository/ApplicationRepository.php`.

## Требования
- **REQ-CASE-09-02.** Новый класс `CarMoneyLab\Repository\NotificationCandidateRepository`
  (или метод с говорящим именем) возвращает кандидатов батча: заявки со статусом
  `decided`, по которым есть хотя бы одно решение и нет записи в протоколе.
  Заявки `new` и `cancelled` не отбираются.
- **REQ-CASE-09-04.** К каждой отобранной заявке присоединяется последнее решение:
  максимальный `created_at`, при равенстве — максимальный `id`.
- Возвращаются поля, нужные письму и протоколу: id заявки, `applicant_ref`, решение,
  `approved_limit`, `created_at` решения.
- **REQ-CASE-09-17.** Только SELECT из `applications`, `decisions` и протокола.
  `AssessmentService`, `DecisionEngine` и другие классы конвейера оценки не меняются.

## Подсказки
- «Последнее решение» удобно получить соединением по составному ключу
  (`application_id`, `created_at`, `id`) с агрегатом или оконной функцией; MySQL 8
  поддерживает оконные функции.
- Для AC-CASE-09-06 вставляйте решения с явно заданным равным `created_at`
  (колонка `created_at` без DEFAULT-подстановки принимает литерал).
- Тестовые строки удаляйте в tearDown (в т.ч. протокол и решения), иначе сломаете
  идемпотентность повторных прогонов.
- Feature-тесты требуют базу: `make up` → `make test`; локально —
  `DB_DSN='mysql:host=127.0.0.1;port=3307;dbname=carmoney_lab;charset=utf8mb4'`.
- Класс `final`, `declare(strict_types=1)` — конвенции AGENTS.md.
