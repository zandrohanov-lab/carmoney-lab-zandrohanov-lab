## Интервью

### Вопрос 1 (из 3): «пробег не указан» — что это?

Как трактовать «пробег не указан» для строки `''`? Сейчас нормализация приводит `''` к `0`,
заявка проходит валидацию и получает решение по LTV; `null` и отсутствие ключа дают 422.
Нужно ли менять валидацию, чтобы `''` тоже возвращал 422, или оставить `''` = 0
и вынести изменение в отдельную задачу?

**Заказчик:** если пробег не указан — это ошибка.

**Решение:** любой неуказанный пробег (`null`, отсутствие ключа, `''`) — 422 с ошибкой поля
`mileage`. В scope входит правка валидации, чтобы `''` перестал приводиться к `0`.

### Вопрос 2 (из 3): HTTP feature-тест на 422

Нужен ли HTTP feature-тест на 422 для заявки без `mileage`? В проекте нет `tests/Feature/`
и изолированной тестовой БД для контроллера с PDO-репозиторием. Альтернатива —
unit-фиксация `ValidationException` в `ApplicationValidatorTest`.

**Заказчик:** пока не знаю.

**Решение:** HTTP feature-тест — открытый вопрос; по умолчанию только unit-фиксация,
feature-тест отложен до появления инфраструктуры.

### Вопрос 3 (из 3): причина перевода в review в ответе API

Должен ли API возвращать причину перевода в `review` из-за пробега (например, поле
`reason`), или достаточно существующего `decision: review`?

**Заказчик:** не нужно.

**Решение:** контракт ответа не меняется, новых полей нет; фронтенд вне scope.

## Итоговое намерение

- После успешной валидации и расчёта LTV: пробег строго больше 400 000 км понижает
  `approve` до `review`; 400000 включительно — `approve`.
- Правило только ужесточает: базовые `review` и `reject` не меняются; `reject`
  не смягчается до `review`.
- Порядок: `validate → LTV → decide`; правило применяется после валидации.
- `approved_limit` пересчитывается существующей логикой: после перевода в `review`
  лимит нулевой.
- Порог — `backend/config/rules.php` (`vehicle.review_mileage_km = 400000`), отдельно
  от валидационной границы `max_mileage_km = 500000`.
- Реализация — пост-обработка в `AssessmentService`; контракт `DecisionEngine` не меняется.
- Пробег не указан (`null`, отсутствие ключа, `''`) — ошибка 422; нужна правка валидации.
- Ответ API без причины перевода; фронтенд не меняется.
- Scope: `rules.php`, `AssessmentService`, `ApplicationValidator`, `AppFactory`,
  unit-тесты.
- Вне scope: фронтенд, схема БД, seed-данные, LTV-пороги, `max_mileage_km`,
  возрастные правила, логика `DecisionEngine` по LTV.
- Открытый вопрос: HTTP feature-тест на 422 (инфраструктура `tests/Feature/`
  не определена).
- Проверка: `make test`, `make lint`.
