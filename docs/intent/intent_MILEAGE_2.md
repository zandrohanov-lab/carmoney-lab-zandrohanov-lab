# Intent MILEAGE (2)

Собран по итогам интервью Grill Me (`docs/intent/grill_MILEAGE.md`, 2026-09-27).

## Замысел

Добавить в расчёт решения по заявке правило по пробегу автомобиля: после успешной
валидации и расчёта LTV пробег строго больше 400 000 км понижает решение `approve`
до `review` (источник: ответ в интервью).

Дополнить валидацию входных данных: любой неуказанный пробег (`null`, отсутствие
ключа, пустая строка) — ошибка 422, а не участие в расчёте решения (источник:
ответ в интервью).

## Зачем

Заявки с очень большим пробегом несут повышенный риск: автоматическое `approve`
по ним должно проходить ручную проверку (`review`) (источник: формулировка задачи
в интервью — docs/README.md).

Неуказанный пробег делает оценку ненадёжной, поэтому такая заявка должна
отклоняться как ошибочный ввод, а не оцениваться (источник: ответ в интервью —
«если пробег не указан — это ошибка»).

## Constraints

- Порог — 400 000 км; перевод в `review` начинается строго выше порога: 400 000
  включительно остаётся `approve` (источник: ответ в интервью).
- Правило только ужесточает решение: понижает `approve` до `review`; базовые
  `review` и `reject` (по LTV) не меняются, `reject` не смягчается до `review`
  (источник: ответ в интервью).
- Порядок обработки сохраняется: валидация → расчёт LTV → решение; правило
  применяется после успешной валидации к уже рассчитанному решению
  (источник: ответ в интервью).
- Неуказанный пробег (`null`, отсутствие ключа, пустая строка) — ошибка
  валидации 422; правило к таким заявкам не применяется (источник: ответ
  в интервью).
- Порог 400 000 — параметр бизнес-правила, задаётся конфигурационно, а не
  хардкодом; отдельно от валидационной границы допустимости пробега 500 000 км,
  которая не заменяется новым порогом (источник: ответ в интервью; код:
  backend/config/rules.php — vehicle.max_mileage_km = 500000).
- Заявка с пробегом 400 001–500 000 получает `review`, а не 422: 422 — только
  для неуказанного пробега (источник: ответ в интервью; код:
  backend/config/rules.php — max_mileage_km = 500000).
- Лимит по заявке после перевода в `review` — нулевой, по существующей логике
  результата; отдельного пересчёта не вводится (источник: ответ в интервью; код:
  backend/src/Domain/AssessmentService.php).
- Контракт ответа API не меняется: существующее поле `decision` без новых полей,
  причина перевода в `review` не возвращается (источник: ответ в интервью).
