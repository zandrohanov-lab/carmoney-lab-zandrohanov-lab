## 1. Бизнес-правило по пробегу (PR #7, ветка `hw1/dz1-zandrohanov-lab`)

### Что меняется для заказчика

- Заявки с пробегом **≥ 400 000 км**, которые по LTV получили бы `approve`,
  теперь уходят в ручное ревью с `approved_limit = 0`.
- Базовые `review` и `reject` по LTV правило не трогает и не смягчает.
- Граница строгая: пробег `399 999` — ещё `approve`, `400 000` и выше — `review`.
- Заявки с пробегом `400 000–500 000` км остаются валидными и уходят в `review`,
  а не в отказ по валидации. Валидационный потолок `500 000` км сохранён.
- Валидация: пробег стал обязательным полем. Отсутствие ключа, `null` или
  пустая строка `''` в `mileage` — это ошибка 422 с указанием поля `mileage`,
  а не «тихий» `review`.
- Контракт ответа API не расширен: новых полей с причиной перевода в `review`
  не добавляли.

### Где это в коде

- Порог правила: `backend/config/rules.php`, блок `vehicle`,
  `review_mileage_km = 400000` (хардкода в коде нет).
- Применение правила после LTV: `backend/src/Domain/AssessmentService.php`.
- Ужесточение валидации `mileage`: `backend/src/Domain/ApplicationValidator.php`.
- Регистрация сервиса: `backend/src/AppFactory.php`.

## 2. Инструменты разработчика: правила ast-index (PR #8, ветка `d2/2.1.1-2.1.4-zandrohanov-lab`)

### Что меняется

Для разработчиков и AI-агентов ввели обязательный порядок поиска по коду:
сначала `ast-index stats` / `rebuild` / `update`, затем `symbol` → `search` →
`usages` / `callers` / `outline`, и только потом `grep` / `rg` для строк
и комментариев. Это закреплено в:

- новом файле `.kilo/rules/ast-index.md` — регламент использования `ast-index`;
- `kilo.jsonc` — файл правил подключён через `instructions`;
- `AGENTS.md` — ссылка на правило `ast-index` для агентов.

### Эффект

Замеры на задаче «сколько файлов трогает правило пробега»
(`Activity.md`, `docs/metrics/tokens_d2.md`):

| Режим       | Input tokens | Output tokens | Cache hit | Шаги |
|-------------|-------------:|--------------:|----------:|-----:|
| без индекса | 101 191      | 2 364         | 85,0%     | 22   |
| ast-index   |  22 530      |   615         | 75,8%     |  4   |

Input снизился примерно в 4,5 раза, выдача — в 3,8 раза, число шагов —
с 22 до 4. Поведение сервиса не меняется, правка только в инструментарии.
