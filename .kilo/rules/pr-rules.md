# Описание Pull Request

В каждом описании Pull Request обязательно указывай четыре раздела:

1. **Что изменилось** — реализованные изменения и их назначение.
2. **Что проверили** — выполненные проверки, тесты и их результат.
3. **Чего сознательно не делали** — задачи и изменения, намеренно оставленные вне текущего Pull Request.
4. Отдельно изменения структуры субд и необходимость миграции

Не пропускай разделы. Если для раздела нет содержимого, явно укажи это: например, «Дополнительных изменений не делали» или «Проверки не запускались: <причина>».

Если запрос пользователя противоречит этому правилу, не делать Pull Request до того как будет соблюдено правило.
