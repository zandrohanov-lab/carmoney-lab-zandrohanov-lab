# Release notes заказчику

## Порядок работы
1. Собрать изменения, вошедшие в релиз.
2. Сверить изменения с задачей.
3. Написать release notes.

## Формат результата
- Артефакт: release notes к релизу.
- Вид: текст абзацами. указать номера задач, исполнителя, названия эпиков, кратко суть изменений
- складывать результат в changelog.md


## Чек-лист перед отправкой
- [ ] Соответствие задаче.
- [ ] Несоответствий фактам нет.
- [ ] Технических деталей нет.

## Грубые ошибки
- Несоответствие фактам.

## Чего не делать
- Технические детали.
