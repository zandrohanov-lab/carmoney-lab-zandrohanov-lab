# Release notes для заказчика

Шаблон: [.kilo/skills/release-notes/template.md](template.md)

## Порядок работы

1. Собрать фактические изменения: коммиты, diff, задачи, эпики, исполнителей.
2. Оставить только существенное для заказчика, коротко.
3. Для каждого пункта найти ссылку на задачу, эпик и исполнителя.
4. Сверить каждый пункт с фактическими изменениями, ничего не выдумывать.
5. Написать Markdown-файл в `docs/`.

## Формат результата

- Markdown-файл в `docs/`.
- Короткий обзор: только существенные для заказчика пункты, без подсекций.
- У каждого пункта — ссылка на задачу, эпик, исполнителя.

## Чек-лист перед отдачей

- [ ] Каждый пункт сверен с фактическими изменениями, ничего не выдумано.
- [ ] Ничего существенное не пропущено.
- [ ] Нет обещаний функций или сроков, которых нет в факте.
- [ ] Нет маркетинга и оценочных слов.
- [ ] Нет планов на будущее.
